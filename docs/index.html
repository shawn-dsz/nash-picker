In one paragraph

Nash already models picking end to end. The exercise's four scenarios map exactly onto statuses that already exist - picked, partially_picked, not_picked and substituted - so this is a mapping problem rather than a domain design problem. OnePick drives Nash's model rather than inventing a parallel one, which is also why it is stateless: there is no database, Nash holds the state, and closing the tab loses nothing.
